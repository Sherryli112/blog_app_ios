- `Views/Home/HomeView.swift`
- `Views/Category/CategoryArticleListView.swift`

將 `.idle, .loading where articles.isEmpty` 拆成兩個獨立 case，行為不變。

## 3. SwiftData 遷移（關閉 #8）

採門面（façade）策略：四個 Store 對外的 `@Observable` API 不變，
views / previews / 測試不需改動，只把內部持久化從 `UserDefaults` 換成 SwiftData。

- 新增 `Storage/PersistenceModels.swift`：
  - `@Model`：`FavoriteArticleEntity`、`HistoryEntity`、`GameProfileEntity`、`AuthSessionEntity`
  - `PersistenceContainer`：共用容器工廠（App 用磁碟、Preview/測試用 in-memory）
- 改寫 `FavoritesStore` / `ReadingHistoryStore` / `GameStore` / `AuthStore`：以 `ModelContext` 讀寫，
  保留無參數 `init()`（Preview）與 `GameStore(profile:)`（測試）
- `App/FuntimeBlogApp.swift`：建立共用 `ModelContainer` 並注入、掛上 `.modelContainer()`

---

## 4. 多帳號註冊（#3 的選定解法）

`Networking/LocalAuthService.swift`：

- 儲存結構由「單一帳號」改為以 email（小寫）為 key 的字典，存於 Keychain key `local_auth_users`
- 註冊只擋「相同 email」或「相同暱稱」，不同帳號可正常註冊；id 自動遞增
- 登入失敗一律回「帳號或密碼錯誤」，不洩漏既有 email
- 自動遷移舊版單一帳號（`local_auth_user`），不遺失既有資料
- 核心保證維持：註冊新帳號不會覆蓋既有帳號

---

## 5. 本地資料依帳號隔離

修正「新帳號卻看到前一帳號的簽到 / XP / 收藏」的問題——根因是三個資料 Store
原本是裝置共用、不分使用者。

- `FavoriteArticleEntity` / `HistoryEntity` / `GameProfileEntity` 新增 `ownerEmail` 欄位
  （預設 `""`，供既有資料平滑遷移為訪客資料）
- 移除收藏 / 歷史 `id` 的 `.unique` 約束（同一篇文章可被不同帳號各自持有）
- 三個 Store 依 `owner` 過濾讀寫，新增 `setOwner(_:)`
- `Views/RootTabView.swift`：啟動時與登入狀態變化時，將三個 Store 切換到目前登入者
  （未登入為訪客範圍）

效果：每個帳號各自保留簽到 / XP / 收藏 / 閱讀歷史，登出再登入資料仍在。
